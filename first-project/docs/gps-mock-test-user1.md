# Chrome Sensors 가짜 GPS 테스트 (userId=1)

백엔드 `GET /api/users/1/guide` 경로 기준.  
총거리 `totalDistanceM ≈ 411.6m` (n10→n14 에스컬레이터 구간 포함).

## 준비

1. 앱을 Chrome에서 연다  
   - 로컬: `http://localhost:5173/?userId=1`  
   - 또는 배포 URL + `?userId=1`  
   > 기본 userId가 5면 오늘 승차권이 없을 수 있음 → **반드시 `userId=1`**
2. S5(길찾기) 화면까지 진입
3. `F12` → `Ctrl+Shift+P` → `Sensors` 검색 → **Sensors** 패널 열기
4. **Location** → **Other… / Custom location**
5. 위치 권한 팝업이면 **허용**

### Sensors 필드

| 필드 | 넣을 값 | 비고 |
|------|---------|------|
| Latitude / Longitude | 아래 시퀀스 | 노드 좌표. 입력 후 **Enter/다른 칸 클릭**으로 확정 |
| **Accuracy** | 무시해도 됨 (150 OK) | 앱은 accuracy로 좌표를 깎지 않음 |
| Orientation | Off여도 거리·음성 테스트 가능 | Off면 「반대 방향」시선 판정 안 함 |

### watch가 안 올 때 (Chrome 한계)

Chrome Sensors는 lat/lng만 바꿔도 `watchPosition`이 **안 불리는 경우**가 있다.  
JS로 watch를 강제로 울릴 수는 없고, 앱은 아래처럼 보완한다.

- **250ms `getCurrentPosition` 폴링** → 좌표 바뀌면 내비 콜백 실행  
- **3초마다 watch 재구독**  
- accuracy / 보행속도 게이트 없음 → Sensors 순간이동도 즉시 반영  

좌표 넣은 뒤 0.5초 안에 콘솔 `[NAV] pass=n0x`가 바뀌면 OK.  
하드 리프레시(`Ctrl+Shift+R`) 후 S5 재진입하면 최신 코드가 적용된다.

### 음성이 안 들릴 때
1. S5 화면을 **한 번 탭**한다 (Chrome 자동재생 잠금 해제)
2. 콘솔에서 `[TTS] guide/steps 로드 완료 | audioMap keys:` 에 n01,n02… 가 있는지 확인
3. 콘솔 `[NAV] s=… | pass=n0x` 가 좌표 넣을 때마다 바뀌는지 확인  
   - `SNAP`이 보이면 Sensors 점프가 바로 반영된 것  
   - s가 안 올라가면 위치 권한이 막혔거나 Sensors 좌표가 앱에 안 들어간 것

### 왜 표랑 숫자가 조금 다르냐

앱 공식은 항상 `남은거리 = totalDistanceM(≈411.6) − s` 이다.

| 원인 | 설명 |
|------|------|
| **BE 누적 ≠ 지도 직선** | n01→n02 `distanceToNextM=18.45m` 인데, lat/lng 직선(Haversine)은 **~9m**. 표 mid는 좌표 평균이라 “길이 절반”과 “지도 중간”이 다름 |
| **s는 경로 투영** | mid에서는 `s = 0 + t×18.45` (t≈0.5 → ≈9.2). 노드에 거의 붙으면 cum으로 스냅 |
| **Sensors 오차** | 좌표를 넣어도 브라우저가 아주 살짝 다른 값을 주면 n02에서 393 대신 387(`s≈24.6`)처럼 보임 |
| **반올림** | UI는 `Math.round` 해서 393.2 → 393 |

즉 표는 **이상적인 목표값**이고, 화면은 **투영/스냅/반올림 결과**라 ±수 m 차이는 정상이다.  
정확히 맞는지 보려면 콘솔 `[NAV] s=… remain=…` 를 본다.
